## Batch 3b — Confirmation core 🔴

`modules/repost/confirmation/` — GET `:dinas` (antrian PENDING + breadcrumb reassign chain dari
`audit_log`) + POST `:dinas/submit` (batch CONFIRM/DECLINE/REJECT_REDIRECT, atomik lewat
`DatabaseService.withTransaction` + `SELECT...FOR UPDATE OF t`). `DinasAccessGuard`
(`core/security/`) diisi implementasi nyata (Batch 0 cuma skeleton `req.identity` ada/tidak): 401
tanpa identity, TAB lolos semua dinas (termasuk Corp), PIC dibatasi dinas sendiri
case-insensitive. Seam `DirectoryProvider` baru (`core/directory/`, pola sama `IdentityProvider`)
— `SeedDirectoryProvider` (dev, baca `employee-directory.seed.json` yang baru dibuat: 22 PIC demo
+ 1 TAB, karena file itu sebenarnya tidak pernah ada di repo — cuma disebut di komentar test lama)
dan `OcxDirectoryProvider` (stub, di luar scope). `DomainError`+`GlobalExceptionFilter` ditambah
field `errorCategory` opsional supaya respons 500 transaksi bisa bawa `error_category` (dari
`classifyError`, 3a) di body JSON.

Diuji lewat HTTP nyata: GET queue 200 + breadcrumb benar, guard 403/200; satu batch submit
CONFIRM+DECLINE+REJECT_REDIRECT sekaligus — CONFIRM hasilkan **tepat 2 ledger entry** (DEBIT
target, CREDIT inisiasi) + `periode_efektif` terisi, DECLINE snapshot juga terisi, REJECT_REDIRECT
→ `dinas_target` pindah + `reassign_count`+1 + `periode_efektif` NULL tanpa ledger; reply comment +
notifikasi mention ter-scope benar ke pasangan (privacy-fix teruji). **Atomicity 🔴**: batch 1
valid + 1 id tak ada → 500 dengan `error_category`, baris valid TETAP tak berubah (rollback total),
`audit_log` action `ROLLBACK` tetap tercatat lewat koneksi terpisah dari pool.

Hasil: 11 suite / 82 test hijau (66 lama + 8 `ConfirmationService` + 7 `DinasAccessGuard` + 1
`SeedDirectoryProvider`).

## Batch 3c — Reassignment inisiator + investigation (Batch 3 tuntas)

Diekstrak dulu (arahan IT eksplisit di prompt, hindari duplikasi 3b/3c):
`modules/repost/shared/pair-comment.service.ts` (reply-ke-thread-pasangan + notifikasi — dipakai
`ConfirmationService`, **direfactor** dari private method, DAN reassignment/investigation;
parameter baru `implicitRecipientDinas` karena confirmation memberitahu `dinas_inisiasi` sedangkan
investigation memberitahu `dinas_target` BARU — dua konvensi berbeda yang route lama masing-masing
hardcode terpisah) dan `modules/repost/shared/rollback-audit.service.ts` (audit ROLLBACK via
koneksi terpisah, port `logger.js`'s `logRollbackAudit`, dipakai ketiga service transaksi).

`modules/repost/reassignment/` — GET `:dinas` (guard `DinasAccessGuard`) + POST `:id/resolve` +
POST `batch-resolve` (satu transaksi, all-or-nothing). `resolveOneDeclined` melempar `DomainError`
langsung (400 action invalid, 403 otorisasi, 404 tak ketemu, 409 bukan DECLINED) — httpStatus-nya
dipertahankan sampai response lewat `wrapRollback`. Otorisasi resolve PER-BARIS (bukan guard,
karena `dinas_inisiasi` baru diketahui setelah `FOR UPDATE`).

`modules/repost/investigation/` — TAB-only (`RolesGuard`+`@Roles('TAB')`) di semua endpoint. GET
`/` + POST `:transactionId/assign` (langsung CONFIRMED + 2 ledger entry, bukan balik ke PENDING —
keputusan TAB final) + POST `assign-all`. Gate all-or-nothing (`transaction_id`+`dinas_target`
wajib per item) dijamin `class-validator` di DTO (`@IsNotEmpty`), bukan dicek manual duplikat.

Diuji lewat HTTP nyata: reassignment — BORNE (`BORNE_BY_INITIATOR`, nol ledger), REASSIGN (target
aktif, PENDING, `reassign_count`+1, `periode_efektif` NULL), **cap REASSIGN_CAP=3** (percobaan
ke-4 ditolak 400, dibuktikan dengan bump manual `reassign_count=3` lalu revert), otorisasi 403/409/
404, `batch-resolve` atomik (1 valid + 1 invalid → baris valid tetap tak berubah, rollback-audit
tercatat). Investigation — TAB-only 403 di 3 endpoint, `assign` → CONFIRMED + tepat 2 ledger +
`reassigned_from='Ask TA'` + comment/notif ke dinas BARU (beda arah dari confirmation, teruji
lewat data nyata), `assign-all` gate 400 (item tanpa target ditolak sebelum apa pun tersentuh) dan
batch sukses → 1 komentar per pasangan DISTINCT (dua transaksi ke pasangan sama = balas ke thread
yang sama, dibuktikan bukan cuma diasumsikan), atomicity (1 invalid → semua batal).

Hasil: 15 suite / 105 test hijau (82 lama + 10 `ReassignmentService` + 6 `InvestigationService` +
4 `PairCommentService` + 3 `RollbackAuditService`).
