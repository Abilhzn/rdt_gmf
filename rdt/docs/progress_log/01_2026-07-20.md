### 2. Audit of Gap 4 — tiered SM/GH export approval (task #6, in-progress)
Dispatched an Explore agent to check the state of the work-in-progress export-batch
feature (untracked `exportBatches.js`, modified `index.js`/`ui-demo.html`). Findings,
**~85% complete**:

- `src/backend/src/routes/exportBatches.js` (new, 181 lines) — Express router, `requireUser` applied globally. Endpoints:
  - `GET /` — list batches (`ADMIN_TAB`/`SM_TA`/`GH_TA`)
  - `POST /` — create `DRAFT` batch (`ADMIN_TAB` only), requires `period`
  - `POST /:id/submit` — `DRAFT → WAITING_SM`; blocked if any `rdt.transactions` row has `status_konfirmasi` in `PENDING`/`DECLINED`/`NEEDS_REVIEW` — **gate is global, not period-scoped, deliberately** (documented in header comment); attaches unbatched `CONFIRMED`/`BORNE_BY_INITIATOR` rows
  - `POST /:id/sm-approve` — `WAITING_SM → WAITING_GH` (`SM_TA`/`ADMIN_TAB`)
  - `POST /:id/gh-approve` — `WAITING_GH → APPROVED` (`GH_TA`/`ADMIN_TAB`)
  - `POST /:id/export` — `APPROVED → EXPORTED` (`ADMIN_TAB` only); writes only a placeholder `STUB_export_batch...csv` filename, no real file content — response explicitly flags `stub: true` with a warning, since the actual SAP export column template isn't known yet (correctly not guessed, per project convention)
- Wiring into `index.js`, the `export_batches` schema table, and role gating are all implemented and internally consistent.

**Gaps identified (nothing changed yet, left for a follow-up decision):**
1. No test coverage at all for export batches — the router talks directly to `pg.Client` with no mock seam, so a test would need either a live test DB or a refactor first.
2. Schema has a `CANCELLED` status but no route implements a reject/cancel-back-to-DRAFT transition.
3. Two design decisions are only documented as code comments, not confirmed with the project owner: the global-vs-period-scoped submit gate, and "submit" semantics generally.

## Decisions / notes worth remembering
- The SAP export endpoint is intentionally a stub — no invented SAP column schema — pending a real template.
- The submit-gate for export batches checks confirmation status **globally**, not per-period, by design (not yet re-confirmed with project owner).
- No cancel/reject flow exists yet for export batches despite `CANCELLED` being a valid schema status.
- Export-batch feature has zero automated test coverage as of this session.

## Open questions carried forward
- Should the export-submit gate stay global or become period-scoped?
- Should a `CANCELLED`/reject transition be added for export batches?
- Test coverage strategy for `exportBatches.js` (needs a DB test seam or a live test DB).
