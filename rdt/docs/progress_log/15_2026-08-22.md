## Dokumen rencana dibuat: `RENCANA_REWRITE_NESTJS.md`

Ditulis sebagai dokumen pegangan tracking, dipakai buat tiga hal: (1) lacak
progres per-batch, (2) jaga konteks antar sesi kerja ke depan (project besar,
multi-sesi), (3) bukti kepatuhan ke tim IT kalau nanti ditanya.

**Keputusan terkunci** (section 1 dokumen, sengaja ditandai "jangan diubah
tanpa alasan kuat"):
1. Framework backend **NestJS** (wajib dari IT, selaras OCX) — module-based,
   DI bawaan, decorator konsisten.
2. Struktur folder `core/` (reusable lintas module) + `modules/` (domain),
   kebab-case, tiap module self-contained.
3. **Tidak ada `modules/auth`** — identity (user/dinas/role) disediakan OCX,
   RDT cuma *membaca* lewat `core/security` (Guard + `@CurrentUser()` +
   `IdentityProvider` mode `OCX | dev-mock`). Login/Select Platform jadi
   urusan cangkang OCX, dibuang dari RDT.
4. Frontend tetap Angular — yang berubah cuma restrukturisasi ke pola
   `core`/`shared`/`features`.
5. DB tetap raw parameterized `pg` dibungkus repository provider (DI),
   **bukan ORM** — biar `FOR UPDATE`+transaksi atomik (jantung kebenaran
   finansial ledger) gak berisiko rusak ketimpa asumsi ORM. Reversible kalau
   OCX ternyata mewajibkan TypeORM (§5 dokumen, alasan lengkap).
6. Storage: MinIO self-hosted di balik `StorageService`, swappable ke MinIO
   OCX nanti tanpa nyentuh parser.
7. Validasi `class-validator`/`class-transformer` + DTO per endpoint.
8. ESLint+Prettier wajib, Swagger buat API docs.

**Guardrail keras yang paling penting** (section 6): saat pindah ke exception
filter global NestJS, scope `BEGIN/COMMIT/ROLLBACK` + `FOR UPDATE` (ledger
atomicity) **tetap wajib di dalam service/unit-of-work** — ROLLBACK harus
kejadian SEBELUM exception naik ke filter, biar gak ninggalin data setengah
jadi. Fokus khusus nanti di Batch 3 (`repost/confirmation`).

**Rewrite masuk folder baru** `rdt/backend-nest/` — backend Express lama di
`rdt/backend/` TIDAK ditimpa, tetap jadi referensi kebenaran & sumber logika
yang di-port. 44 test lama (parser + ledger) jadi jangkar kebenaran, wajib
di-port ke Jest dan tetap hijau di setiap batch.

**8 batch direncanakan** (semua status ⬜ Belum per akhir sesi ini):
0. Fondasi (scaffold NestJS + `core/` + infra — belum ada logika bisnis)
1. `repost/upload` (parser + pivot cache + test)
2. `repost/mapping` (mapping + exclusions)
3. `repost/confirmation` (state machine + transaksi atomik)
4. `repost/export` (Format TAB + batch/subdoc)
5. Pendukung (comment/notification/dashboard/audit)
6. Frontend Angular (restrukturisasi clean-code)
7. Finishing (lint/dead-code/Swagger/pre-merge)

**3 deviasi dari PDF, sudah disadari & dicatat transparan buat handoff ke IT**
(section 7): (1) gak nyalin pohon folder opex/capex 100% — gak ada akses ke
struktur aslinya, cuma ngikutin prinsipnya; (2) raw `pg` bukan ORM (lihat
poin 5 di atas); (3) versi NestJS+library gak bisa disamain persis punya OCX
(gak ada akses) — dicatat biar IT bisa rekonsiliasi versi pas integrasi nanti.
