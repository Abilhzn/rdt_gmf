dicek langsung ke `main.ts`, bukan diasumsikan). 2 unit test interceptor (7 assertion) — sempat
butuh perbaikan `tsconfig.spec.json`/`tsconfig.app.json` (`include`/`exclude` path relatif ke
`rdt/` lewat symlink `dev-shell/src/app/rdt`) supaya spec di luar `dev-shell/src/` ikut ke-compile.

## Batch 6b — Repost (Upload/Persist)

`pages/repost-budgeting/` (1 file monolitik) dipecah jadi `features/repost/`: page + 3 dumb
component (`file-dropzone`, `aggregation-matrix`, `preview-table`). Kontrak diganti total ke
Format CBO (`repost/upload/parse` + `repost/persist`) dari format 53-kolom lama. **Temuan
penting**: prompt batch ini mengklaim status `INVALID` "sudah tidak ada" — diverifikasi langsung
ke `excel-parser.service.ts` (`resolveStatus`) dan CHECK constraint schema, ternyata klaim itu
salah (`INVALID` masih nyata muncul saat nominal tak terbaca). `TransactionStatus` di frontend
dibuat mengikuti CHECK constraint asli (`migrations/013_upload_supersede.sql`, 10 nilai termasuk
`SPLIT_VOID`/`SUPERSEDED`), bukan klaim prompt. Kolom preview di-hardcode (Format CBO 12 kolom
fixed, tidak ada lagi `GET /api/contract-fields`).

## Batch 6c — Confirm

Komponen terbesar (994 baris .ts+.html, 6 konsep backend dalam satu file) dipecah jadi
`features/confirmation/`: `confirm-page` (SMART, orkestrasi) + `pending-queue`/

## Batch 6d — Dashboard + Dashboard-detail

`home/` + `dashboard-detail/` dipindah ke `features/dashboard/` (nested route dipertahankan persis
seperti semula, sidebar tetap aktif di halaman drill-down). Tidak dipecah lebih jauh dari page —
beda dari Confirm, ini satu konsep kohesif (progress card + KPI + rollup), bukan gabungan banyak
backend berbeda. `getBreakdown()` diperbaiki: response asli `{dinas_inisiasi, pairs}`, bukan array
polos seperti diasumsikan draft awal — ketahuan dari baca `dashboard.controller.ts` langsung.

## Batch 6e — Export

`need-approval/` → `features/export/pages/waiting-page` (TAB-only), `repost-history/` →
`history-page` (bukan TAB-only, force-scoped server-side). Format TAB 8-kolom jadi satu-satunya

dipromosikan ke `core/utils/blob-download.util.ts` — sebelumnya cuma dipakai lokal di 6c, sekarang

## Batch 6f — Admin + Setting-periode + Share-cost (penutup Batch 6)

Tiga panel TAB-only kecil: `admin/` → `features/admin/` (mapping=merge/upsert vs
exclusions=replace-all, dibuat eksplisit lewat hint text + reload-setelah-simpan di UI, bukan
cuma dipercaya di server), `setting-periode/` → `features/period-deadlines/` (reminder banner

dumb component, running-total validator). `downloadOriginal` dipromosikan ke
`core/services/original-file-download.service.ts` (dipakai Confirm + Share-cost).

File service lama (`transaction.service.ts`, `export-batch.service.ts`, `confirmation.service.ts`
