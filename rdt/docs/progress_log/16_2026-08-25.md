## Batch 1 — repost/upload (parser Format CBO)

Port `rdt/backend/src/parser/excelParser.js` → `modules/repost/upload/parser/excel-parser.service.ts`
(satu service, dipecah stepdown jadi method kecil satu tanggung jawab — header discovery, resolusi
dinas_target, resolusi status, helper cell/angka). Logika & urutan precedence status (termasuk
quirk "nominal invalid overwrite EXCLUDED" dari kode lama) dipertahankan persis, dikomentari
eksplisit. Dua entry point: `parseFile(path)` (dipakai test) & `parseBuffer(buffer)` (dipakai
controller — `StorageService` cuma expose Buffer, boundary storage tetap bersih). Seed
`mapping.seed.json`/`dinas.codes.json`/`exclusions.config.json` di-copy ke
`modules/repost/upload/config/` (module-local, sengaja — Batch 2 pindah sumbernya ke DB lewat
override param yang sudah disiapkan di sini). `RowStatus` ditambah `NEEDS_INVESTIGATION`.
Endpoint `POST /repost/upload/parse` (multipart, DTO+ValidationPipe) — upload → simpan via
`StorageService` → parse → rows + rekap per (status, dinas_target). `persist` ke DB DITUNDA.

Port `test/parser.test.js` → 4 test Jest, angka **identik** kode lama: TB 469 baris (TC 94732.21,
TF 360.21, TJ 46353.37, TL 112867.35, TN 860.64, Corp 3294.95); TJ 490 baris (TE 84.36, TMM
473933.51, TA 1653.24, 3× NEEDS_INVESTIGATION = 40393.29, 0 NEEDS_REVIEW). Endpoint juga
diverifikasi manual lewat `curl` HTTP nyata, angka sama persis.

## Batch 2 — repost/mapping (DB jadi sumber kebenaran)

`modules/repost/mapping/`: `MappingService` (`rdt.dinas_mapping`, `upsertMany` = merge/upsert via
`ON CONFLICT...DO UPDATE`, **withTransaction**), `ExclusionService` (`rdt.exclusion_rules`,
`replaceAll` = DELETE+re-INSERT, **withTransaction** — semantik beda dari mapping, disengaja, ikut
`index.js` lama), `RoutingConfigService` (assemble `{mapping, exclusions, dinasCodes}` dari DB —
dinasCodes **tanpa filter is_active**, beda dari picker). `modules/master-data/` baru —
`DinasService.listActive()` (`WHERE is_active=true`, buat picker) + `.listAllCodes()` (unfiltered,
buat routing), `GET /dinas`. `core/security`: `@Roles()` + `RolesGuard` baru, TAB-only di
`GET/PUT /repost/mapping` & `GET/PUT /repost/exclusions`.

`ExcelParserService` dari Batch 1 **tidak diubah sama sekali** — sudah dirancang menerima override
opsional sejak awal, jadi `upload.controller.ts` tinggal suntik `RoutingConfigService.assemble()`.

Terverifikasi lewat HTTP nyata lawan `rdt_dev`: merge vs replace (keduanya benar dan beda semantik
kebukti), role gate (403 non-TAB), **rollback transaksi** (PUT 2 entry, entry ke-2 sengaja langgar
FK → 500, kedua entry — termasuk yang valid — gagal masuk, `withTransaction` benar), parser via DB
→ angka identik Batch 1. Satu temuan: `GET /dinas` balikin **23** baris aktif, bukan 24 seperti
perkiraan prompt — roster nyata di `rdt_dev` punya **5** dinas nonaktif (TG/TK/TO/TT + **TAB**,
`is_active=false` sejak migration `014_tab_share_cost_target.sql`), bukan 4. Query-nya sendiri
persis sama dengan `index.js` lama — dikonfirmasi bukan bug, prompt-nya yang kelewat baris TAB.
Data uji (mapping `XYZ`, exclusions `FOO`, rollback-test) dibersihkan balik ke seed semula setelah
verifikasi.

`npm test` tetap hijau di semua 4 batch (6 test di akhir sesi: 2 sanity + 4 parser, tak ada yang
pecah oleh batch berikutnya). `npm run build`/`lint` bersih tiap batch.
