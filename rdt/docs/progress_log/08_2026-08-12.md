## Bagian 2 — Checklist 1.2: security headers, rate limiting, session expiry

Dikerjakan dengan protokol eksplisit dari user: **rencana dulu (terutama
nilai CSP yang aman buat Angular — jangan sampai block resource sendiri),
tunjukkan, baru eksekusi** — lalu **jelaskan konsepnya dulu, baru kasih
quick-question/decision**. Hasil `AskUserQuestion`: session TTL **8 jam**,
tooling test **tambah supertest**.

- `helmet` dipasang di ketiga service (`auth`, `data_user`, `rdt/backend`)
  dengan CSP yang dikalibrasi supaya gak block resource Angular dev-shell
  sendiri.
- `express-rate-limit` di `POST /login` — 5 percobaan gagal / 15 menit,
  429 bukan 401 generik, `skipSuccessfulRequests=true`.
- Session store in-memory di `auth` diubah dari "hidup selamanya" jadi
  `{ user, expiresAt }` dengan TTL 8 jam (`SESSION_TTL_HOURS`
  configurable), kode error `SESSION_EXPIRED`/`INVALID_SESSION` dibedakan
  supaya bukan 401 generik.
- Sempat ketemu bug: header security gak muncul di DevTools — root cause
  `angular.json`'s `serve.options.headers` cuma dibaca saat `ng serve`
  start, gak hot-reload. Fix: restart `dev-shell`, verifikasi via curl
  dulu sebelum minta user cek ulang.

## Bagian 7 — Loading-state audit + error-message pattern (Phase 9)

Instruksi: *"coba jalanin loading-state audit sekalian error-message
pattern-nya. sama klo ada yang belum dikerjakan, kerjain aja."*

**Error-message pattern**: pattern `err?.message || err` (30 titik
panggilan di 8 komponen) bikin `HttpErrorResponse` Angular nunjukin pesan
generik ("Http failure response for...") bukan pesan asli backend. Dibuat
helper `shared/error-message.util.ts` (`extractErrorMessage(err,
fallback)`), semua 30 titik diganti.

**Loading-state audit** — grep subscribe-calls vs loading-mentions per
komponen, ketemu 3 gap nyata:
- **`admin/mapping-editor.component.ts` & `admin/exclusions-editor.component.ts`
  — REGRESI dari checklist 1.1 sendiri** (bagian 6 di atas): kedua
  komponen ini masih pakai `fetch()` mentah tanpa auth header sama
  sekali, rusak total begitu guard `requireUser`/`requireRole('TAB')`
  masuk ke `/api/mapping`/`/api/exclusions`. Ditulis ulang pakai
  `AdminService` baru (`CurrentUserService.authHeaders()`) + loading/saving
  flag + `ModalService`.
- `home.component.html` — flag `loaded` ada tapi cuma gate empty-state,
  gak ada indikator "lagi dimuat" — ditambah teks "Memuat dashboard...".
- `repost-history.component.ts` — gak ada flag loading sama sekali,
  `!batches.length` dipakai dobel buat "masih loading" DAN "emang kosong"
  — ditambah flag `loading` + pesan terpisah.
- **`confirm.component.ts`** — gap terbesar: 6 aksi async
  (`submitDecisions`, `resolveBorne`, `resolveReassign`,
  `submitAllResolutions`, `assignInvestigation`, `assignAllInvestigation`,
  `bulkAssignSelected`) sama sekali gak ada busy-state guard — ditambah
  flag per-aksi, tombol `[disabled]` + teks "Menyimpan..." selama
  in-flight.
- `share-cost`, `setting-periode`, `need-approval` diverifikasi baris-per-
  baris sudah benar (gak ada gap). `shell.component.ts` — 6 subscribe tapi
  semua background/suplementer, gak butuh busy-state UI.

Success-feedback audit: semua aksi finansial/mutating dicek punya
`modal.success()`/`modal.alert()` di jalur sukses — gak ada gap.

`ng build` bersih, `rdt/backend` 82/82, `auth` 13/13. `CHECKLIST_LAUNCH.md`
