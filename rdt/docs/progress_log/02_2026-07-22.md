### Bugs found and fixed via live end-to-end testing (not just unit tests)
Running the real `contoh_input` file (8,373 rows) through the full
parse→persist→confirm pipeline surfaced three serious, stacked bugs, each
hidden behind the previous one:
1. **Express's default 100kb body-size limit** — persist requests for
   large files (several MB) were silently rejected with an HTML error
   page, which is exactly the `<!DOCTYPE ...` "not valid JSON" error the
   user reported. Fixed by raising the JSON body limit.
2. **`uploads.original_filename` NOT NULL constraint** — neither frontend
   was sending it. Fixed on both `ui-demo.html` and the Angular
   `transaction.service.ts`.
3. **PostgreSQL's hard 65,535-bind-parameter limit** — a single INSERT
   with 65 columns × 8,373 rows blew far past it. Fixed by chunking the
   insert while keeping it inside one atomic transaction.

Also fixed:
- **"Dinas Pengunggah" dropdown only ever showed 2 options** — it was
  wired to `/api/mapping` (Excel-prefix normalization exceptions like
  `TCR→TC`, only 2 rows) instead of `/api/dinas` (the real 22-dinas
  table, `rdt.dinas`). Rewired to the correct endpoint; separately, per
  user request, the whole dropdown was later removed and the uploader
  dinas auto-derived from the logged-in account instead.
- **Stuck modal on page load** — a CSS specificity tie between `.hidden`
  and a later `.modal-overlay { display:flex }` rule meant the modal
  showed regardless of the `hidden` class. Fixed by making `.hidden` the
  last, always-winning rule in the sheet.

## Decisions and corrections worth remembering

- **"Agent looping" ≠ literal parallel execution** here — Fable's plan
  explicitly rejected full parallelism because the repo had no git safety
  net yet and several gaps touch the same files; serial execution in
  dependency order was used instead.
- **Auth claim shape is `{dinas, role}` from the start**, not just
  `{dinas}` — done deliberately so Gap 4's SM/GH role checks wouldn't
  require revisiting Gap 2 later.
- **"Dinas Pengunggah" is not a manual choice** — it tags every parsed
  row's `dinas_inisiasi` and drives self-billing exclusion (a dinas
  doesn't bill itself; those rows become `EXCLUDED`, not `PENDING`). User
  corrected this should be auto-derived from the logged-in account, not a
  dropdown — real GMF IT identity mapping is still a separate open item.
- **Figma colors/shadows/layout are binding, not just structural
  reference** — this was an explicit correction of an earlier assumption
  made this same session; SRS.md's "colors not binding" note applied to
  an earlier draft, not this round's design.
- **Popups must be in-page centered modals**, never native browser
  `confirm()`/`alert()` — applied across both frontends via a shared
  modal service/component.
- **Dev DB gets truncated after each verified round** during this active
  UI-iteration phase, per explicit user instruction, so every manual test
  starts from a clean slate (reference data like the dinas list is
  preserved, only transactional tables are wiped).
- The user shared the local Postgres password in chat to unblock DB
  access; the assistant held it only in the running process's environment
  (never wrote it to any file) and explicitly flagged it should be
  considered exposed/rotate-worthy since it's now in the transcript.
- An unexplained external edit to `.claude/settings.json` (statusline
  config replaced by an `acceptEdits`/deny-list permissions block) was
  observed mid-session, not authored by the assistant, and was
  deliberately left out of every commit rather than guessed at or reverted
  — origin never resolved within this session.
